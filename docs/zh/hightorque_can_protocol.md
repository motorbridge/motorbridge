## 1. 协议总览

### 1.1 总线参数

- 电气接口：CAN 2.0（经典帧）
- 波特率：仲裁段 1 Mbps，数据段 1 Mbps
- 数据段：小端序（低字节在前）——除 MIT 位打包帧外，所有 16 位数据均为小端

### 1.2 协议 ID 结构（16 位）

高擎协议在 16 位 ID 域内编码源/目的地址与回复开关：

| 位段 | 含义 |
|---|---|
| bit15 | **回复总开关**：1 = 需要电机回复；0 = 无需回复。置 1 但不发查询指令时，电机会返回一帧数据段长度为 0 的帧（2026-10-09 candump 真机证实：`05 13` 力矩帧 + bit15 → 电机回 `id<<8`、DLC=0 空帧，仅此一帧，**无任何状态数据**；2026-10-24 复测 `01 00 00` + bit15 同样只回 DLC=0 空帧，标准裸 id 帧则零回帧） |
| bit14~bit8 | 源地址（7 位）。主机通常用 0 |
| bit7 | 固定 0 |
| bit6~bit0 | 目的地址（7 位），即电机 CAN_ID，**0x7F 为广播地址** |

示例：

- `0x8001`：源 0、目的 1、回复开关开——主机向 1 号电机查询
- `0x0100`：源 1、目的 0、回复开关关——**1 号电机的回复帧**（电机回复一律把自身 id 放在源地址字段，即 `id << 8`）

**16 位 ID 放在 CAN 帧的哪里**：16 位是协议自定义的**逻辑地址结构**（协议 PDF §1.1「ID：由 16 位构成」），不是 CAN 硬件仲裁域的宽度。发送时把这个 16 位数值直接当作 CAN 仲裁 ID 用——装得进 11 位就发标准帧，装不下（或需要 bit16 标记）就发 29 位扩展帧。参考固件 `can_send` 的判定就一行：`id > 0x7FF ? 扩展帧 : 标准帧`（`my_can.c:171`）：

```
扩展 29 位帧（0x8000|id，查询/配置）：
  bit28……bit16   bit15    bit14~bit8   bit7   bit6~bit0
  全 0            回复开关  源地址(=0)    0      目的 id
  （MIT 帧 0x18000|id：bit16 额外置 1 作为模式标记，低 16 位仍是 0x8000|id）

标准 11 位帧（裸 id，控制）：
  bit10~bit8   bit7   bit6~bit0
  0            0      目的 id         ← 只装 16 位协议 ID 的低 11 位
```

- **扩展帧**：协议 ID 占 29 位仲裁 ID 的低 16 位，高 13 位为 0（MIT 帧额外置 bit16，bit16 属于 16 位结构之外的扩展标记位，协议 PDF 未定义，来自 v2.0.0 参考固件）；
- **标准帧**：只承载低 11 位（bit10~bit0），前提是高 5 位全 0——控制帧（回复开关 0、源 0）满足，直接以裸目的 id 发送不丢信息；电机回复帧的协议 ID 为 `id<<8`，id ≤ 7 时小于 `0x800` 同样装得进标准帧。

### 1.3 帧承载与回复 ID

| 帧类别 | CAN 帧型 | 仲裁 ID | 说明 |
|---|---|---|---|
| 控制类（普通/协同/梯形/力矩/DQ/停止/刹车） | **标准 11 位帧** | `电机 id`（1~127） | 参考固件 `can_send(fdcan, id, ...)`，裸目的地址 |
| 查询/配置类（寄存器读、零位、保存、周期上报、版本） | **扩展 29 位帧** | `0x8000 \| 电机 id` | bit15 回复开关置 1，源地址 0 |
| MIT 运控（固件 v4.6.0+） | **扩展 29 位帧** | `0x18000 \| 电机 id` | bit16+bit15 置位（含回复开关），源地址 0 |
| 电机回复（状态/寄存器回读/ACK/版本） | 标准帧（id ≤ 7）/扩展帧 | `电机 id << 8` | 源=电机 id，目的=0（主机），如 id=1 → `0x0100`；id ≥ 8 时超出 11 位需扩展帧 |
| 一拖多广播 | 扩展 29 位帧 | `0x8080`~`0x80AF` | 见 §7 |

> ⚠️ 注意：01-CAN协议解析.pdf §1.4 的示例代码将停止帧写成 `0x8000 | id` 扩展帧，与 v2.0.0 参考固件库（`set_motor_stop` 发裸 id 标准帧）**不一致**。以参考固件为准：控制类用标准帧裸 id。工程实践中可两种都发以兼容旧固件。
>
> 📌 2026-09-29 更新（**2026-10-09 已证伪并退回**）：motorbridge vendor 层的 `send_control` 曾默认改为 PDF §1.4 写法——控制类命令以扩展 29 位帧 `0x8000|id` 发送并置 bit15 回复总开关，预期 v2.0.0 固件对每个控制帧回发 §3.2 的状态反馈帧。**2026-10-09 candump 真机证伪**：bit15 置于非查询指令（如 `05 13` 力矩）上，电机只回一帧 `id<<8`、DLC=0 的空帧（即 §1.2 PDF 原文行为），没有任何状态数据——扩展写法换来的只是每个控制帧一个无用空帧的总线开销。**2026-10-09 起 `send_control` 已退回本表写法**：控制类标准 11 位裸 id（参考固件原行为，与 §10 逐函数一致）；`set_control_reply(true)` 保留为诊断/复现开关（vendor 层，未接到 ABI/Python）。

### 1.4 电机支持的控制模式

- **普通模式**：位置+力矩 或 速度+力矩（二者不可同时，靠 `0x8000` 填充位区分）
- **协同模式**：位置、速度、力矩同时控制
- **梯形模式**（v4.6.0+）：位置、速度、加速度
- **运控模式 / MIT**（v4.6.0+）：位置、速度、力矩、Kp、Kd，位打包一帧
- **力矩模式**：纯力矩
- **DQ 电压 / DQ 电流模式**：直接给 Q 相电压/电流
- **停止 / 刹车**：模式 0 / 模式 15

## 2. 通信命令说明

以下示例默认目标电机 `CAN_ID = 0x01`。

### 通信命令 1：普通模式控制指令（`0x07 0x07`）

一帧 8 字节：指令位（2 字节）+ 位置（2 字节）+ 速度（2 字节）+ 力矩（2 字节）。位置与速度不能同时控制，不被控制的量填 `0x8000`（`INT16_NAN`，表示无限制）。

| 数据域 | 11 位 ID | 8Byte 数据区 |
|---|---|---|
| 大小 | bit10~0 | Byte0~Byte7 |
| 描述 | 目标电机 CAN_ID | 07 07 pos1 pos2 val1 val2 tqe1 tqe2 |

| 字段 | 单位（int16 raw） | 说明 |
|---|---|---|
| pos | 0.0001 圈/LSB | 5000 = 0.5 圈；`0x8000` = 无限制（速度+力矩控制时） |
| vel | 0.00025 圈/s/LSB | 1000 = 0.25 圈/s；`0x8000` = 无限制（位置+力矩控制时） |
| tqe | 0.01 N·m/LSB | 110 = 1.1 N·m；`0x8000` = 无限制 |

**举例 1（位置控制）**：转到 0.5 圈，最大力矩 1.1 N·m，速度不限——

```
仲裁 ID：0x001（标准帧）    数据：07 07 88 13 00 80 6E 00

07 07    指令位：普通模式
88 13    位置 0x1388 = 5000  → 0.5000 圈
00 80    速度 0x8000 = INT16_NAN → 无限制
6E 00    力矩 0x006E = 110   → 1.10 N·m
```

**举例 2（速度控制）**：以 0.25 圈/s 运行，力矩不限——

```
仲裁 ID：0x001（标准帧）    数据：07 07 00 80 E8 03 00 80

00 80    位置 0x8000 = INT16_NAN → 无限制
E8 03    速度 0x03E8 = 1000  → 0.25 圈/s
00 80    力矩 0x8000 → 无限制
```

应答帧：无——控制类命令不产生应答（置 bit15 也只回一帧 DLC=0 空帧，见 §1.2）；状态刷新走 `17 01` 查询（3.1）或周期上报（§8.1）。

### 通信命令 2：协同控制指令（`0x07 0x35`）

位置、速度、力矩同时控制，一帧 8 字节：指令位（2）+ 速度（2）+ 力矩（2）+ 位置（2）。**注意字段顺序是 vel、tqe、pos**。

| 数据域 | 11 位 ID | 8Byte 数据区 |
|---|---|---|
| 大小 | bit10~0 | Byte0~Byte7 |
| 描述 | 目标电机 CAN_ID | 07 35 val1 val2 tqe1 tqe2 pos1 pos2 |

`0x8000` 填充仍表示该量无限制（如 `vel=5000, tqe=1000, pos=0x8000`：电机以 0.5 圈/s 持续旋转，最大力矩 0.1 N·m）。

**举例**：以 0.5 圈/s 转到 0.5 圈，限制最大力矩 0.1 N·m——

```
仲裁 ID：0x001（标准帧）    数据：07 35 D0 07 0A 00 88 13

07 35    指令位：协同控制
D0 07    速度 0x07D0 = 2000  → 0.5 圈/s
0A 00    力矩 0x000A = 10    → 0.10 N·m
88 13    位置 0x1388 = 5000  → 0.5000 圈
```

### 通信命令 3：梯形控制指令（`0x07 0x2d`，固件 v4.6.0+）

以目标加速度加速、按目标速度运动到目标位置。一帧 8 字节：指令位（2）+ 位置（2）+ 速度（2）+ 加速度（2），**字段顺序 pos、vel、acc**。

| 数据域 | 11 位 ID | 8Byte 数据区 |
|---|---|---|
| 大小 | bit10~0 | Byte0~Byte7 |
| 描述 | 目标电机 CAN_ID | 07 2D pos1 pos2 val1 val2 acc1 acc2 |

| 字段 | 单位（int16 raw） |
|---|---|
| pos | 0.0001 圈/LSB |
| vel | 0.00025 圈/s/LSB |
| acc | 0.001 圈/s²/LSB（400 = 0.4 圈/s²） |

> 2026-11-02 修正：acc 单位以**飞书寄存器单位表**为准（0.001 圈/s²/LSB），与固件 `convert.c` `acc_float2int`（TINT16 scale=1000）一致；本节原按旧宿主库 `libelybot_can.c` 注释误写 0.01 圈/s²/LSB（40 = 0.4 圈/s²），已弃用，举例原始值随之由 40 改为 400。仓库实现（ACC_SCALE int16=1000）与飞书一致，无需改动。

**举例**：以 0.4 圈/s² 加速度、0.25 圈/s 速度运动到 0.5 圈——

```
仲裁 ID：0x001（标准帧）    数据：07 2D 88 13 E8 03 90 01

88 13    位置 5000  → 0.5000 圈
E8 03    速度 1000  → 0.25 圈/s
90 01    加速度 400  → 0.4 圈/s²
```

协议文档 §2.3 建议：普通位置模式运动剧烈，**位置控制优先用梯形模式**。

### 通信命令 4：运控模式 MIT 指令（`0x18000 | id`，固件 v4.6.0+）

输出力矩 = (目标位置 − 当前位置) × kp + (目标速度 − 当前速度) × kd + 前馈力矩。
扩展 29 位帧 `0x18000 | id`，数据 8 字节**位打包**（不是小端字节序！）：

| 字段 | 位宽 | 位置 | 量程 | 换算 |
|---|---|---|---|---|
| pos | 16 bit | Byte0~1（低字节在前） | −3.2768 ~ +3.2767 圈 | 0.0001 圈/LSB |
| vel | 12 bit | Byte2（低 8 位）+ Byte3 低 4 位 | −2.0 ~ +2.0 圈/s | 1/1024 圈/s/LSB |
| tqe | 12 bit | Byte3 高 4 位 + Byte4 | −10 ~ +10 N·m | 5/1024 N·m/LSB |
| kp | 12 bit | Byte5（低 8 位）+ Byte6 低 4 位 | −400 ~ +400 | 800/4096/LSB |
| kd | 12 bit | Byte6 高 4 位 + Byte7 | −100 ~ +100 | 200/4096/LSB |

数值编码为**偏置无符号线性映射**（各量独立）：

```
raw = (x − MIN) × (2^bits − 1) / (MAX − MIN)，超界饱和
例：pos = 0 → 0x8000（32768，半量程）；vel = 0 → 0x800（2048）
    pos = 0xA6F0（42768）→ (42768−32768)×0.0001 = +1.0 圈
```

位拼装（对应参考固件 `motor_control_pos_vel_tqe_kp_kd` 的移位顺序）：

```
b0 = pos & 0xFF
b1 = (pos >> 8) & 0xFF
b2 = vel & 0xFF
b3 = ((vel >> 8) & 0x0F) | ((tqe & 0x0F) << 4)   // vel 高 4 位 | tqe 低 4 位<<4
b4 = (tqe >> 4) & 0xFF
b5 = kp & 0xFF
b6 = ((kp >> 8) & 0x0F) | ((kd & 0x0F) << 4)     // kp 高 4 位 | kd 低 4 位<<4
b7 = (kd >> 4) & 0xFF
```

**举例**：pos = +1.0 圈，vel = +1.0 圈/s，tqe = +5.0 N·m，kp = 200，kd = 50。四个 12 位量编码后恰均为 `0xC00`，便于核对拼装规则——

```
仲裁 ID：0x18001（扩展帧）    数据：F0 A6 00 0C C0 00 0C C0

F0 A6   pos = 0xA6F0 = 42768（Byte0~1）
        → 42768 × 0.0001 − 3.2768 ≈ +1.0000 圈
00 0C   vel = 0xC00 = 3072（Byte2 低 8 位 + Byte3 低 4 位）
        → 3072 × (1/1024) − 2.0 = +1.0 圈/s
0C C0   tqe = 0xC00 = 3072（Byte3 高 4 位 + Byte4）
        → 3072 × (5/1024) − 10.0 = +5.0 N·m
00 0C   kp = 0xC00 = 3072（Byte5 低 8 位 + Byte6 低 4 位）
        → 3072 × (800/4096) − 400 = +200
0C C0   kd = 0xC00 = 3072（Byte6 高 4 位 + Byte7）
        → 3072 × (200/4096) − 100 = +50
```

注意相邻字段**共享边界字节**：`00 0C C0` 三个字节同时装下 vel 与 tqe（Byte3 低半字节属 vel、高半字节属 tqe），末尾 `00 0C C0` 同样装下 kp 与 kd——这正是位打包帧与小端帧的区别。

应答帧：无。MIT 帧 ID 自带 bit15/bit16，但同 §1.2 规则——非查询指令，电机最多回一帧 DLC=0 空帧，无状态数据；状态刷新走查询或周期上报。

> 注意：MIT 的 vel 量程（±2.0 圈/s）与协同/普通模式的速度编码（int16 线性、无此量程限制）是两套体系。

### 通信命令 5：力矩模式指令（`0x05 0x13`）

纯力矩控制，实际是向力矩寄存器 0x13 写 int16。一帧 4 字节：指令位（2）+ 力矩（2）。

| 数据域 | 11 位 ID | 4Byte 数据区 |
|---|---|---|
| 大小 | bit10~0 | Byte0~Byte3 |
| 描述 | 目标电机 CAN_ID | 05 13 tqe1 tqe2 |

**举例**：输出 1.1 N·m——

```
仲裁 ID：0x001（标准帧）    数据：05 13 6E 00

05 13    指令位：力矩模式（写寄存器 0x13）
6E 00    力矩 110 → 1.10 N·m（0.01 N·m/LSB）
```

### 通信命令 6：运行模式设定指令（`0x01 0x00 <mode>`）

写运行模式寄存器 0x000（表1）。帧族为 `01 00 <模式号>`，模式号取自表2：

| 功能 | 帧（标准帧，裸 id） | 表2 模式号 |
|---|---|---|
| **停止（并清除错误）** | `01 00 00` | 0 |
| DQ 电压模式 | `01 00 08` + `05 1B <volt16>`（可拼一帧 7 字节） | 8 |
| DQ 电流模式 | `01 00 09` + `05 1C <cur16>`（可拼一帧 7 字节） | 9 |
| **刹车** | `01 00 0F` | 15 |

- 停止（模式 0）：电机三相悬空，可自由转动，**同时清除错误**（表2 模式 0 名称即「停止，清除错误」——停机与清错一帧两效，协议无独立清错命令）。
- 刹车（模式 15）：所有相短接到地，阻尼刹车，阻力与转速正相关。
- DQ 电压/电流：模式切换 + 目标寄存器写（0x1B Q 电压 / 0x1C Q 电流）**拼在同一帧**：

**举例 1（停止）**：

```
仲裁 ID：0x001（标准帧）    数据：01 00 00    （3 字节）
```

**举例 2（DQ 电压 1 V，0.1 V/LSB）**：

```
仲裁 ID：0x001（标准帧）    数据：01 00 08 05 1B 0A 00    （7 字节）

01 00 08   写模式寄存器 0x000 = 8（DQ 电压模式）
05 1B 0A 00 写寄存器 0x1B = 10 → Q 相电压 1.0 V
```

**举例 3（刹车）**：

```
仲裁 ID：0x001（标准帧）    数据：01 00 0F    （3 字节）
```

### 通信命令 7：通用寄存器读取（`0x17` 命令族）

读任意寄存器（表1）。扩展帧 `0x8000 | id`，数据区为一到多对 `{cmd, addr}`：

```
发送：{cmd, addr [, cmd1, addr1, ...]}        回复：{cmd', addr, 数据... [, cmd'', addr'', 数据...]}
```

**cmd 位域**（收发同构，方向位不同）：

| 位段 | 发送 | 回复 |
|---|---|---|
| [7:4] | `0001` = 读取 | `0010` = 回复 |
| [3:2] | 00 = int8，01 = int16，10 = int32，11 = float | 同左（回读类型） |
| [1:0] | 01 = 1 个，10 = 2 个，11 = 3 个 | 同左（个数） |

CAN 一帧 8 字节减去 cmd+addr 共 2 字节，最多读：1 个 float/int32，或 3 个地址连续的 int16，或 6 个地址连续的 int8。

> ⚠️ **真机更正（2026-10-24，can0 实测，candump 证据）**：上段"可将多个 `{cmd, addr}` 拼接"的写法在 v2.0.0 固件上**不可用**——固件只解析帧内**第一对** `(cmd, addr)`，其余字节必须**全零**：
>
> | 发送帧（dlc / 数据） | 回帧 |
> |---|---|
> | 2 / `17 01` | ✅ `27 01 …`（延迟 ~0.45 ms） |
> | 3-8 / `17 01 00…`（零尾随） | ✅ 正常回帧（dlc 8 零填充 = 旧 B1 帧型，同样受理） |
> | 4 / `15 00 16 0E`（两对） | ❌ **零回帧**（整帧静默丢弃，连 DLC=0 空帧都没有） |
> | 6 / `17 01 15 00 16 0E`（三对） | ❌ 零回帧 |
>
> 结论：**读请求一帧一对**，非连续地址分多帧发（`17 01` 之后紧接 `15 0E` 各自 2 字节）。回帧侧 cmd 半字节自描述段类型（`27/25/26`），逐帧解析不受影响。真机时序：单 socket 连发 3 帧，电机按请求顺序**串行回帧**（回帧间隔 ~210-250 µs，单帧延迟 ~0.5-0.6 ms，3 帧总用时 ~1.02 ms）。
>
> 2026-10-22 决策：仓库的读路径（vendor/ABI/CLI/网关/Python）**固定使用 int16**（cmd[3:2] 恒 01），并按 §4「读换算」列把回复换算为物理量返回——协议本身仍支持四种类型位域（上表），但仓库不再让调用方选择；其它主机发的 int8/int32/float 回复帧仍能被解码入缓存。
>
> 同日追补决策：读/写的目标地址必须全部在**表1（0x00-0x45）**内——缺号与表外地址一律整段报错、零发帧（见 §4「地址准入」）。
>
> 2026-10-24 追补：vendor `request_registers` 对多条 ReadCmd **逐帧连发**（一帧一对，各 2 字节 dlc）；整组地址先校验后发送，任一越界整组零帧拒绝。

**举例 1（读运行模式，1 个 int8）**：

```
仲裁 ID：0x8001（扩展帧）    数据：11 00

11     cmd = 0b0001_0001：读 / int8 / 1 个
00     从地址 0x00（模式寄存器 0x000）开始

回复（id 0x0100 标准帧）：21 00 0A

21     cmd = 0b0010_0001：回复 / int8 / 1 个
00     地址 0x00
0A     模式值 = 10（位置模式，查表2）
```

**举例 2（读位置 3 个 int16 + 读温度 1 个 int16——分两帧发）**：

```
仲裁 ID：0x8001（扩展帧）    数据：17 01        （帧 1：读 / int16 / 3 个，从 0x01）
仲裁 ID：0x8001（扩展帧）    数据：15 0E        （帧 2：读 / int16 / 1 个，从 0x0E）
```

回复逐帧到达：先 `27 01 <pos16> <vel16> <tqe16>`（8 字节，恰占满），后 `25 0E <temp16>`（4 字节）。**不要把两对拼进一帧**（如 `17 01 15 0E`）——真机上整帧被静默丢弃，见上方更正注。地址连续的寄存器可并入一帧的 count 段：如温度 0x0E + 错误码 0x0F 连读即 `16 0E`（回复 `26 0E <temp16> <fault16>` 一帧带回）。

### 通信命令 8：电机状态读取（`0x17 0x01`）

命令 7 的特例（也是日常最常用的查询）：从地址 0x01 连读 3 个 int16 = 位置/速度/力矩。

```
仲裁 ID：0x8001（扩展帧）    数据：17 01

17     0b0001_0111：读 / int16 / 3 个
01     从 0x01 开始
```

**回复（id 0x0100 标准帧，8 字节）**：

```
27 01 38 F6 09 00 00 00

27 01   回复 / int16 / 3 个，从 0x01 开始
38 F6   位置 0xF638 = −2505 → −0.2505 圈
09 00   速度 0x0009 = 9 → 0.00225 圈/s
00 00   力矩 0
```

> **2026-10-24 仓库行为（`request_feedback` / `request_motor_feedback`）**：非阻塞连发**两帧**——`17 01`（本命令）+ `16 0E`（温度 0x0E + 错误码 0x0F，见命令 7 举例 2 注；真机实测两帧总线流水线占用 ~1 ms）。接收端语义：`27 01` 回帧**锚定一次状态计数**（状态缓存序号 +1、received_at 刷新，即"一帧状态"）；`26 0E` 回帧**就地补丁** `t_mos`/`fault_code`（×0.1°C / 与表3 1:1，不推进序号、不刷新时间戳）——两回帧合为一次状态计数，消费方按序号感知的"新状态"频率与单帧版一致。`request_fresh_state` 的新鲜度仍只由 `27 01` 锚定帧定义。

### 通信命令 9：通用寄存器写入（`0x05 <reg>` 族）

向 R/W 寄存器写值（表1），数据区 `{05, reg, val…}`。**帧形态按用途分两类**（与 §1.3 一致）：控制目标寄存器走标准帧裸 id，配置类走扩展帧 `0x8000 | id`：

| 帧 | 写入对象 | 帧形态 | 说明 |
|---|---|---|---|
| `05 13 <tqe16>` | 寄存器 0x13 力矩 | 标准帧裸 id（4 字节） | 即通信命令 5（力矩模式） |
| `05 1B <volt16>` | 寄存器 0x1B Q 电压 | 拼进 DQ 电压模式帧（见通信命令 6） | 0.1 V/LSB |
| `05 1C <cur16>` | 寄存器 0x1C Q 电流 | 拼进 DQ 电流模式帧（见通信命令 6） | 0.1 A/LSB |
| `05 B3 02 00 00` | 保存设置 | 扩展帧 `0x8000\|id`（5 字节） | 见通信命令 12 |
| `05 B4 02 <t_ms16>` | 周期上报设置 | 扩展帧 `0x8000\|id`（5 字节） | 见通信命令 10 |

（写运行模式寄存器 0x000 不走本族，走专用 `01 00 <mode>`，见通信命令 6。）

### 通信命令 10：周期返回电机状态（`0x05 0xB4`）

让电机按周期主动上报位置/速度/力矩，格式与 `0x17 0x01` 回复相同（§3.1）。

| 数据域 | 29 位 ID | 5Byte 数据区 |
|---|---|---|
| 大小 | `0x8000\|id` | Byte0~Byte4 |
| 描述 | 查询/配置帧 | 05 B4 02 t1 t2 |

- 周期单位 ms，**最小 1 ms**；`t = 0` 停止周期返回（或给电机断电）。

**举例**：开启 10 ms 周期上报——

```
仲裁 ID：0x8001（扩展帧）    数据：05 B4 02 0A 00

0A 00   周期 10 ms
```

此后电机每 10 ms 发一帧 `27 01 <pos16> <vel16> <tqe16>`（id `0x0100`）。

### 通信命令 11：重置电机零位（`0x40`）

将当前位置设为机械零位。**只在 RAM 中修改**，需配合通信命令 12（conf write）保存到 flash；建议本指令后延时约 1 s 再发保存。

| 数据域 | 29 位 ID | 7Byte 数据区 |
|---|---|---|
| 大小 | `0x8000\|id` | Byte0~Byte6 |
| 描述 | 查询/配置帧 | 40 01 04 64 20 63 0A（固定序列） |

```
仲裁 ID：0x8001（扩展帧）    数据：40 01 04 64 20 63 0A
```

注意：需先让电机停止后再置零，否则无效。

### 通信命令 12：保存电机设置（conf write，`0x05 0xB3`）

将电机 RAM 中设置保存到 flash，**使用后建议给电机重新上电**。

```
仲裁 ID：0x8001（扩展帧）    数据：05 B3 02 00 00    （5 字节）
```

应答帧：设置 ACK（见 §3.3）。

### 通信命令 13：固件版本读取（`0x15 0xB5 0x02`）

```
仲裁 ID：0x8001（扩展帧）    数据：15 B5 02    （3 字节）
```

**回复**（id `0x0100` 标准帧，5 字节）：`15 B5 02 <b3> <b4>`，版本号拆位：

```
major = b4 >> 4
minor = (b4 & 0x0F) | (b3 >> 4)
patch = b3 & 0x0F

例：15 B5 02 00 46 → major=4, minor=6, patch=0 → 固件 v4.6.0
```

（参考例程 `motor.c` 仅校验 `data[1]==0xB5 && data[2]==0x02` 签名，byte0 不校验。）

**驱动侧说明**：motorbridge 已移除版本查询接口（`request_firmware_version` 全链路删除，2026-10-17）。原因：该回复为 5 字节事务帧，被动收帧路径（后台线程）不识别、无缓存，同步 `bus.recv` 与后台排空线程在共享 RX 队列上竞态，真机随机超时（评审 A1）。本节保留协议帧格式，仅供 candump 侧调试或日后按"被动解码入缓存 + 序号等待"模式重实现时参考。

## 3. 电机回复帧格式

电机回复的仲裁 ID = `电机 id << 8`（源=电机 id，目的=0）。id ≤ 7 时该值小于 `0x800`，可由标准 11 位帧承载（协议文档示例均属此类）；id ≥ 8 时超出 11 位范围，需以扩展帧承载。参考固件主机侧统一按 `Identifier >> 8` 取源地址解析，与帧型无关。

### 3.1 寄存器读取回复（`0x27`）

见通信命令 7/8。帧头 `27 <addr>`，后接数据（小端）。例：`27 01 38 F6 09 00 00 00`。

> 2026-10-23 决策（仓库实现）：`27 01` 状态查询回复只携带位置/速度/力矩，**不含**运行模式/故障码/温度——这些字段入状态缓存时**不覆盖旧值**（此前实现置 0，一次状态查询会把状态反馈帧带来的故障码冲掉）。运行模式/故障码的帧来源是 §3.2 状态反馈帧（byte0/byte1），但注意 v2.0.0 真机上该帧无已知生产者（见 §3.2 更正：控制命令只回 DLC=0 空帧，周期上报发的是 `27 01` 格式）——**真机上主动拿故障码的仅有路径是读寄存器 0x0F**。
>
> 2026-10-24 补充：0x0F 错误码 raw 值与表3 的对应关系经用户确认（2026-10-23）为**直接 1:1**；同日起 vendor 接收端把寄存器回帧中的 0x00/0x0E/0x0F **桥接进状态缓存**（就地补丁，不推进状态计数，见命令 8 注）——`request_feedback` 的两帧查询之后，`get_state` 即可读到 t_mos 与 fault_code（真机实测：温度 32.0-32.3°C、错误码 0）。

### 3.2 状态反馈帧（周期上报 / 状态编码格式）

此 8 字节帧（len=8，`data[0] != 0x27`）的**产生路径**：`05 B4` 周期上报开启后，电机按设定周期主动发送（§8.1，格式与 `0x17 0x01` 回复一致）。

> ⚠️ 更正（2026-10-09）：本文早期版本称"v2.0.0 固件下电机收到控制类命令会回发此帧"——该说法已被 candump 真机证伪：控制帧（含置 bit15 的扩展帧）只换来一帧 DLC=0 空帧（§1.2），**控制命令不产生本帧**。上位机边控制边刷新状态，须开周期上报或另发 `0x17 0x01` 查询。

| 字节 | 含义 |
|---|---|
| Byte0 | 运行模式（表2，0~17） |
| Byte1 | 故障码（表3，0~47） |
| Byte2~3 | 位置（int16，小端，0.0001 圈/LSB） |
| Byte4~5 | 速度（int16，小端，0.00025 圈/s/LSB） |
| Byte6~7 | 力矩（int16，小端，0.01 N·m/LSB） |

**举例**（id=1 电机，位置模式下）：

```
仲裁 ID：0x0100（标准帧）    数据：0A 00 88 13 E8 03 6E 00

0A      模式 = 10（位置模式，查表2）
00      无故障
88 13   位置 5000  → 0.5 圈
E8 03   速度 1000  → 0.25 圈/s
6E 00   力矩 110   → 1.10 N·m
```

判别规则（与 3.1 区分）：`len==8 && data[0]==0x27` 为寄存器回复；`len==8 && data[0]!=0x27` 为状态反馈帧。

### 3.3 设置确认 ACK 帧

设置类命令（零位 `0x40`、保存 `0x05 0xB3` 等）成功后，电机回 7 字节 ACK：

```
仲裁 ID：0x0100（标准帧）    数据：41 01 04 4F 4B 0D 0A

4F 4B 0D 0A = "OK\r\n"
```

见通信命令 13。

## 8. 电机部分功能说明

1. **周期上报**：默认关闭，通过通信命令 10（`05 B4 02 <t>`）开启；上报格式与 `0x17 0x01` 回复一致，最小 1 ms，`t=0` 停止。
2. **零位保存两步走**：`0x40` 只改 RAM，须再发 `05 B3 02 00 00` 落盘；置零前先停止电机，置零后延时约 1 s 再保存，保存后建议重新上电。
3. **状态刷新只有两条路**：`0x17 0x01` 主动查询（回 3.1 寄存器回复）或周期上报（命令 10，电机主动发 §3.2 帧流）。控制命令**不**附带状态反馈帧——早期文档版本与 2026-09-29 的实现曾如此声称，2026-10-09 candump 真机证伪：bit15 置于非查询指令只回一帧 DLC=0 空帧（§1.2）。
4. **停止 ≡ 清错**：表2 模式 0 名称为「停止，清除错误」，`01 00 00` 一帧两效；协议层没有独立的清错命令。
5. **`0x8000` 填充（INT16_NAN）**：普通/协同模式中表示「该量无限制/不控制」。
6. **单位与数据类型可配置**：参考固件支持转（默认）/弧度/度三种单位（`MOTOR_DATA_TYPE_FLAG`）与 int8/int16/int32/float 四种数据类型（`0x17` 命令族按位域选择）；本文示例均按默认「转 + int16」。
7. **型号力矩/PID 补偿**：参考固件按电机型号对力矩做 `(tqe − d) / k` 补偿后再编码（例 M5047_09 k=0.547474、M5047_36 k=0.64，d=0；M5047_36 固件两版均为 0.35，2026-10-20 决策按厂商寄存器单位表取 0.64），kp/kd 亦有 `pid_adjust` 型号补偿。这是主机侧参考库的换算约定，不影响线上帧格式。仓库自加的 M5036_36（HTDW-5036-02 模组，固件表无此型号）同样取单位表 k 表值 0.64（模组手册 Kt=0.54 Nm/A 是扭矩常数，与 k 不同概念）。

## 9. 控制模式使用说明（调用序列）

以参考固件 API 表述（`motor_set_*` 一帧完成控制；状态需另行 `motor_read(id)` 查询或开周期上报）：

- **位置模式**：`motor_set_pos(portx, id, pos)` —— 以最大速度/加速度运动到目标位置（运动剧烈，推荐改用梯形）
- **速度模式**：`motor_set_vel(portx, id, vel)`
- **协同模式**：`motor_set_pos_vel_MAXtqe(portx, id, pos, vel, tqe)`
- **梯形模式**（v4.6.0+）：`motor_set_pos_vel_acc(portx, id, pos, vel, acc)`
- **运控/MIT**（v4.6.0+）：`motor_set_pos_vel_tqe_kp_kd(portx, id, pos, vel, tqe, kp, kd)`，需设置合适的 kp/kd，否则控制效果差
- **力矩模式**：`motor_set_tqe(portx, id, tqe)`（`05 13` 写寄存器）
- **DQ 电压**：`motor_set_dq_vlot(portx, id, volt)`（V）；**DQ 电流**：`motor_set_dq_current(portx, id, cur)`（A）
- **停止/刹车**：`motor_set_stop(portx, id)` / `motor_set_brake(portx, id)`
- **状态查询**：`motor_read(id)`（`17 01`）或开周期上报；**版本**：`0x15 0xB5 0x02`

与 RobStride 的差异：高擎**无使能帧、无模式切换前置流程**——控制帧本身即触发对应模式（模式由指令字节/模式寄存器决定），上电即可发控制命令；停机用 `01 00 00`。

## 10. 程序样例（C，摘自参考固件 can_h730_v2.0.0.zip）

```c
/* ---- libelybot_can.c：字节级成帧 ---- */

/* 普通模式-位置+力矩（标准帧，裸 id） */
void motor_control_pos(FDCAN_HandleTypeDef *hfdcanx, uint8_t id, int32_t pos, int16_t tqe)
{
    static uint8_t tdata[] = {0x07, 0x07, 0x0A, 0x05, 0x00, 0x00, 0x80, 0x00};
    my_memcpy(&tdata[2], &pos, sizeof(int16_t));   /* Byte2-3 位置 */
    my_memcpy(&tdata[6], &tqe, sizeof(int16_t));   /* Byte6-7 力矩 */
    can_send(hfdcanx, id, tdata, sizeof(tdata));
}

/* 协同控制（标准帧）：Byte2-3 速度、Byte4-5 力矩、Byte6-7 位置 */
void motor_control_pos_vel_MAXtqe(FDCAN_HandleTypeDef *hfdcanx, uint8_t id,
                                  int16_t pos, int16_t vel, int16_t tqe)
{
    static uint8_t tdata[] = {0x07, 0x35, 0, 0, 0, 0, 0, 0};
    my_memcpy(&tdata[2], &vel, sizeof(int16_t));
    my_memcpy(&tdata[4], &tqe, sizeof(int16_t));
    my_memcpy(&tdata[6], &pos, sizeof(int16_t));
    can_send(hfdcanx, id, tdata, sizeof(tdata));
}

/* 梯形控制 v4.6.0+（标准帧）：Byte2-3 位置、Byte4-5 速度、Byte6-7 加速度 */
void motor_control_pos_vel_acc(FDCAN_HandleTypeDef *hfdcanx, uint8_t id,
                               int16_t pos, int16_t vel, int16_t acc)
{
    static uint8_t tdata[] = {0x07, 0x2d, 0, 0, 0, 0, 0, 0};
    my_memcpy(&tdata[2], &pos, sizeof(int16_t));
    my_memcpy(&tdata[4], &vel, sizeof(int16_t));
    my_memcpy(&tdata[6], &acc, sizeof(int16_t));
    can_send(hfdcanx, id, tdata, sizeof(tdata));
}

/* 运控/MIT v4.6.0+（扩展帧 0x18000|id，位打包） */
void motor_control_pos_vel_tqe_kp_kd(FDCAN_HandleTypeDef *hfdcanx, uint8_t id,
                                     int16_t pos, int16_t vel, int16_t tqe,
                                     int16_t kp, int16_t kd)
{
    static uint8_t tdata[8] = {0};
    tdata[0] = pos & 0xff;
    tdata[1] = (pos >> 8) & 0xff;
    tdata[2] = vel & 0xff;
    tdata[3] = ((vel >> 8) & 0x0f) | ((tqe & 0x0f) << 4);
    tdata[4] = (tqe >> 4) & 0xff;
    tdata[5] = kp & 0xff;
    tdata[6] = (kp >> 8) & 0x0f | ((kd & 0x0f) << 4);
    tdata[7] = kd >> 4;
    can_send(hfdcanx, 0x18000 | id, tdata, sizeof(tdata));
}

/* DQ 电压（标准帧 7 字节）：模式写 + 寄存器写拼帧 */
void motor_control_volt(FDCAN_HandleTypeDef *hfdcanx, uint8_t id, int16_t vol)
{
    static uint8_t tdata[] = {0x01, 0x00, 0x08, 0x05, 0x1b, 0x00, 0x00};
    my_memcpy(&tdata[5], &vol, sizeof(int16_t));
    can_send(hfdcanx, id, tdata, sizeof(tdata));
}

/* 停止（标准帧，3 字节，等价清错） */
void set_motor_stop(FDCAN_HandleTypeDef *fdcanHandle, uint8_t id)
{
    static uint8_t cmd[] = {0x01, 0x00, 0x00};
    can_send(fdcanHandle, id, cmd, sizeof(cmd));
}

/* 读状态（扩展帧 0x8000|id） */
void send_read_motor_state(FDCAN_HandleTypeDef *hfdcanx, uint8_t id)
{
    static uint8_t tdata[] = {0x17, 0x01};
    can_send(hfdcanx, 0x8000 | id, tdata, sizeof(tdata));
}

/* ---- motor_control.c：浮点→raw 换算（MIT） ---- */

void motor_set_pos_vel_tqe_kp_kd(port_t portx, const uint8_t id,
                                 const float pos, const float vel, float tqe,
                                 float kp, float kd)
{
    FDCAN_HandleTypeDef *fdcanHandle = motor_get_fdcan_pointer(portx);
    const motor_type_t model = motor_get_model2(portx, id);
    const float tqe1 = tqe_adjust(tqe, model);    /* 型号力矩补偿 */
    const float kp1  = pid_adjust(kp, model);
    const float kd1  = pid_adjust(kd, model);

    const uint16_t pos2 = mit_float2int(pos, -3.2768f, 3.2767f, 16);
    const uint16_t vel2 = mit_float2int(vel, -2.0f,   2.0f,    12);
    const uint16_t tqe2 = mit_float2int(tqe, -10.0f,  10.0f,  12);
    const uint16_t kp2  = mit_float2int(kp,  -400,    400,    12);
    const uint16_t kd2  = mit_float2int(kd,  -100,    100,    12);

    motor_control_pos_vel_tqe_kp_kd(fdcanHandle, id, pos2, vel2, tqe2, kp2, kd2);
}

/* ---- convert.c：偏置无符号线性映射（固件无饱和，调用方需自保证量程） ---- */
uint16_t mit_float2int(float x, float x_min, float x_max, unsigned int bits)
{
    float span = x_max - x_min;
    return (uint16_t)((x - x_min) * ((float)((1 << bits) / span)));
}

/* ---- motor.c：状态反馈帧 / 寄存器回复 / ACK / 版本的收帧判别 ---- */
if (len == 8 && p_data[0] == 0x27 && p_data[1] == 0x01) {
    /* 寄存器读取回复：位置/速度/力矩（小端 int16） */
} else if (len == 8 && p_data[0] != 0x27) {
    /* 状态反馈帧：byte0=模式(表2)、byte1=故障(表3)、byte2-7=pos/vel/tqe */
} else if (len == 7 && p_data[0] == 0x41 && p_data[1] == 0x01 && p_data[2] == 0x04
          && p_data[3] == 0x4F && p_data[4] == 0x4B && p_data[5] == 0x0D && p_data[6] == 0x0A) {
    /* 设置 ACK："OK\r\n" */
} else if (p_data[1] == 0xB5 && p_data[2] == 0x02) {
    /* 固件版本回复（5 字节） */
}
/* 电机回复的 id 取法：id = fdcan_rx_header.Identifier >> 8（源地址字段） */
```
