# Release Test Notes - 0.5.3

Date: 2026-09-05

## Scope

This release adds a pre-enable zero-point safety gate on the arm
`enable_all` path for the Robstride and Damiao vendor links. No other
behavior changes.

## Key Changes

- Added pre-enable zero-point safety gate on `enable_all` for
  `RobstrideController` and `DamiaoController`:
  - When motor `id == 7` is registered, reads its current position before
    energizing; refuses the whole `enable_all` (no motor energized) if the
    position is outside tolerance.
  - Robstride: `get_parameter_f32(0x7019)` (mechPos), ±5° tolerance.
  - Damiao: `get_register_f32(80)` (p_m), ±3° tolerance.
  - Skips silently when no motor 7 is registered; treats non-finite
    (NaN/Inf) and lock-poisoned errors as failures.

## Required Local Checks

```bash
cargo fmt --all -- --check
cargo clippy -p motor_vendor_robstride -p motor_vendor_damiao
cargo test -p motor_vendor_robstride -p motor_vendor_damiao
```

Zero-point gate smoke (needs a real motor at id 7 on `can0`):

```bash
# Robstride: enable_all runs the gate; at zero it passes, off-zero it refuses.
cargo run -p motor_cli -- --vendor robstride --channel can0 \
  --motor-id 0x07 --feedback-id 0x00FD --mode enable
# Damiao: control modes run the gate (mode=enable bypasses it by design).
cargo run -p motor_cli -- --vendor damiao --channel can0 \
  --motor-id 0x07 --feedback-id 0x11 --model 4310 --mode mit \
  --pos 0 --vel 0 --kp 2 --kd 1 --tau 0 --loop 50 --dt-ms 20
```

## Notes

- The gate is enforced only at the vendor-controller `enable_all` layer
  (ABI `motor_controller_enable_all`, Python/C++ `enable_all()`, CLI
  control modes). Single-motor `motor.enable()` paths (e.g. ws_gateway
  `handle_enable`, Damiao CLI `--mode enable`) bypass the gate by design.
