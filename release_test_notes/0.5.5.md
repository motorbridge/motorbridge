# Release Test Notes - 0.5.5

Date: 2026-09-10

## Scope

WebSocket gateway stateless-op (`set_id`/`verify`) PCAN channel release fix, plus
version-alignment release across Rust / Python / C++ / ABI.

## Key Changes

- `set_id` and `verify` now release the active session bus before opening their
  own bus on `ctx.target.channel`, avoiding `PCAN_ERROR_INITIALIZE` on
  Windows/macOS PCAN when the session already holds the channel (the common case
  after `set_target` + stream-enable commands reconnect via `ensure_connected`).
- Version bump `0.5.4` -> `0.5.5` across Cargo, Python `_version.py`, C++ CMake,
  and `bindings/api_surface.json`; EN/ZH testing guides repoint to this note.

## Required Local Checks

```bash
cargo fmt --all -- --check
cargo build -p motor_abi
cargo check -p ws_gateway
cargo test --workspace --all-targets
```

## Hardware-in-the-Loop (PCAN, Windows/macOS)

- Connect a RobStride or Damiao motor on a PCAN channel.
- `set_target` to that channel, then enable state and param streams.
- Run `set_id` and `verify` against the same channel: confirm no
  `PCAN_ERROR_INITIALIZE` and the op succeeds.
- Confirm state/param streams resume (reconnect via `ensure_connected`) after
  the op without a manual reconnect.

## Dangerous Command Boundaries

- `set_id` writes a new device ID to the motor; verify the target motor and ID
  before running, and prefer a single-motor bus to avoid addressing the wrong
  device.
