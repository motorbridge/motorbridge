# Release Test Notes - 0.6.0

Date: 2026-11-11

## Scope

HighTorque native `ht_can` v2.0.0 migration end-to-end (vendor crate, C ABI,
Python SDK, motor_cli, ws_gateway), mixed-vendor shared bus, state snapshot
metadata across all vendors, RobStride fixes (rs-05el model, parameter
reply validation, run_mode i8 write, 0x30xx register removal), mcu-serial
documentation and capability-table alignment, and serial-port default
fixes. Hexfellow is unchanged (CAN-FD only, still socketcanfd).

## Key Changes

- HighTorque v2.0.0 protocol stack: bit-packed MIT frame `0x18000 | id`
  (firmware v4.6.0+), trapezoid `07 2d`, `pos_classic` `07 07`, torque
  `05 13` (physical N·m, model coeff), DQ voltage/current, run-mode switch,
  brake, periodic report `05 B4`, generic register access over the `17`/`05`
  families; fault codes 0-47 and run modes 0-17 decoded; extended-frame
  reply-ID high-byte fix.
- Mixed-vendor shared bus: `new_shared(core)` on every vendor controller;
  several vendors share one bus and one RX drain thread.
- HighTorque state query is non-blocking (`request_feedback` sends and
  returns; `request_fresh_state` blocks for fresh state). Control-frame
  reply-flagging (`set_control_reply`, extended `0x8000|id` + bit15) is
  diagnostics-only and off by default (standard bare-id frames).
- Register reads fixed Int16, converted physical values, table-address
  validation, two-frame feedback (`17 01` + `16 0E`, `26 0E` patches
  t_mos/fault/status, absent fields no longer overwritten).
- `get_state_snapshot()` everywhere: cached state + age (ns in the C ABI,
  `feedback_age_s` elsewhere) + per-motor sequence; only complete state
  updates advance the sequence.
- Breaking removals (see CHANGELOG Removed): hightorque typed param FFI
  family, `--ty`, and the firmware-version query.
- RobStride: rs-05el model, parameter-reply identity validation, run_mode
  written as i8 (usage change), 0x30xx host-tool-only registers dropped.
- Docs: mcu-serial added to all channel-compatibility tables, transport
  legends, CLI/SDK references; hightorque protocol reference and audit
  docs; stale "version (firmware)" capability rows removed.

## Required Local Checks

```bash
cargo fmt --all -- --check
cargo build -p motor_abi
cargo check -p ws_gateway
cargo test --workspace --all-targets
```

Python bindings (from `bindings/python`):

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 \
PYTHONPATH=src LD_LIBRARY_PATH=../../target/debug \
python3 -m pytest tests/
```

Known pre-existing failure (not introduced by this release):
`tests/test_scan.py::RobstrideScanTests::test_robstride_scan_uses_one_controller_at_a_time`
— the test patches `scan.Controller`, but `_scan_robstride` now builds
controllers via `_open_controller`, so the patch no longer intercepts.

## Hardware-in-the-Loop (classic CAN bus + HighTorque v2.0.0 firmware)

- HighTorque full-surface walkthrough:
  `python bindings/python/examples/hightorque_all_interfaces_demo.py can0 1 <model>`
  (also with `--transport mcu-serial --serial-port /dev/ttyACM0
  --serial-baud 921600`). Verify scan → enable → mit/pos-vel/vel/pos-classic/
  torque → read-reg (physical values, register names) → write-reg →
  periodic-report → brake → rezero → conf-write.
- Two-frame feedback: after `request_feedback`, `get_state` carries
  t_mos/fault/status patched from `26 0E`; a `27 01`-only query must not
  zero previously cached fault/mode fields.
- clear_error: confirm the stop frame clears a latched fault (no standalone
  clear-error command exists).
- pos_classic with `"tqe": "1.5"` (string) must return an error and send
  nothing; omitted `tqe` stays intentionally unlimited.
- Mixed-vendor shared bus: one `can0`, one hightorque + one robstride motor,
  both controlled through controllers sharing a `CoreController`.
- RobStride: write run_mode as i8; enable active reporting and confirm state
  frames are no longer dropped.
- State snapshot: call `get_state_snapshot()` twice around a control loop;
  `feedback_age_s` grows between updates and `feedback_sequence` only
  advances on complete state updates.
- mcu-serial (XIAO-C5 bridge): scan each classic-CAN vendor
  (`--transport mcu-serial --serial-port /dev/ttyACM0 --serial-baud 921600`);
  trigger a bus fault and confirm a structured `BusStatus` error instead of
  a bare timeout.
